Conveyor Assembly

A belt carries parts past workers standing on either side. A worker grabs the parts it needs, assembles them over several ticks, then waits for an empty cell to put the finished product down. Every tick the belt shifts one cell right; whatever falls off the end is counted as waste, and a fresh cell arrives on the left.

The contested resource

Only one worker may touch a cell per tick. In the original assignment the north worker always wins — south only gets the cell if north did nothing with it. A worker that is mid-assembly does not need the cell, so it never blocks; and a blocked worker can still keep assembling.

Switch Cell priority to Alternate and watch the north/south split in the status box. North-first costs south about a fifth of its output and buys no extra throughput at all — the rule is purely about who gets the work, not how much gets done.

What the numbers mean

  • Efficiency — finished products per belt movement. The headline number.
  • Wasted — raw parts that rode the whole belt untouched. With a short belt or slow assembly, most of the input is thrown away.
  • In hands — parts picked up but not yet built into anything.

Reproducibility

Every run is driven by one seeded generator, so the same seed and settings replay the same run exactly — in the browser and under node --test. Copy setup puts the whole configuration on the clipboard; Load setup takes it back.

Sweep

Sweep runs the simulation headlessly across a grid of belt lengths and assembly times and prints the efficiency surface to the browser console. No animation, a few thousand ticks each — this is what the model is actually for.

How it is built

The rules live in life-conveyor-core.js, a pure module with no DOM, shared with the Node tests in life-conveyor-core.test.js. Parts are integers and recipes are data — {out, inputs, time} — so more subparts, more products, multi-stage assembly (a product used as an input) and alternative delivery policies are configuration, not new code.

Try the just-in-time supply

The Just-in-time option replaces the random feed with a perfect alternating delivery — exactly the parts needed, in order, no gaps ever. Throughput collapses to almost nothing.

That is not a fault. A finished product needs an empty cell to leave on, and a supply that never sends a gap never provides one, so every worker ends up permanently holding a product it cannot put down. The idle cells in the random feed are not waste — they are the output channel. A real line needs outbound capacity as much as it needs parts, and any delivery schedule worth the name has to reserve some.
